# Public documentation rules

These rules apply to every public-facing file in this directory.

1. Write one sentence per source line

   When text should render as one paragraph, place each sentence on its own source line.
   Do not add blank lines between those sentences.
   This keeps the raw Markdown easy to read without changing the rendered paragraph.

2. Keep punctuation simple

   Do not use em dashes.
   Do not use semicolons.
   Do not end bullet items with periods.
   Rewrite the sentence with a comma, a colon, parentheses, or separate sentences instead.

3. Write for the public

   Use clear and simple language because these files are public-facing.
   Explain unfamiliar terms when they are necessary.
   Focus on what players, contributors, and visitors need to know.
   Keep internal planning notes, agent instructions, private infrastructure details, and unresolved discussions out of public documentation.
